# 법적 리스크 분석 (Legal Risk)

## 개요

기업 운영 중 발생할 수 있는 법적 리스크를 체계적으로 식별·평가·대응하는 분석을 제공한다. 판례 및 법령 리서치, 지적재산권(IP) 포트폴리오 관리, 계약·규제 리스크 매핑을 포함하며 2026년 개정 개인정보보호법, 노란봉투법 등 최신 법령 변화를 반영한다.

**면책 고지: AI 보조 분석이며 전문 법률 자문을 대체하지 않습니다**

## 트리거 키워드

법적 리스크, 법률 리서치, 판례 검색, 지적재산, 특허, 상표, 저작권, IP 전략, 법적 위험 평가, 컴플라이언스, 규제 리스크, 법령 분석, 영업비밀, 오픈소스 라이선스

## 워크플로우

### 1단계: 리스크 도메인 식별

사용자의 상황에서 관련 법령 영역 파악:

**주요 리스크 도메인:**
- **개인정보·데이터** (개인정보보호법, 정보통신망법)
- **노동·인사** (근로기준법, 노동조합법, 퇴직급여보장법)
- **지적재산권** (특허법, 상표법, 저작권법, 영업비밀보호법)
- **공정거래·경쟁** (공정거래법, 표시광고법)
- **금융·투자** (자본시장법, 전자금융거래법)
- **계약·거래** (민법, 상법, 전자상거래법)
- **환경·안전** (산업안전보건법, 중대재해처벌법)

### 2단계: 2026년 최신 법령 변화 체크

> 2026년 개정 법령 변화 목록(개인정보보호법·노동 관련·K-IFRS 제1118호)은 `sz:compliance-check` references/2026-law-changes.md 단일 SSOT를 참조한다.

### 3단계: 리스크 매핑 및 평가

**리스크 매트릭스:**
```
리스크 평가 = 발생 가능성 × 영향도

높음(H): 즉시 대응 필요
중간(M): 3개월 내 대응 계획 수립
낮음(L): 모니터링 유지
```

**리스크 평가 항목:**
| 리스크 | 관련 법령 | 최대 제재 | 발생 가능성 | 영향도 | 우선순위 |
|--------|-----------|-----------|------------|--------|----------|

### 4단계: 지적재산권(IP) 포트폴리오 분석

**특허 (특허법):**
- 특허 등록 현황 확인 (KIPRIS 특허정보검색서비스)
- 경쟁사 특허 침해 리스크 분석
- 핵심 기술 특허 출원 전략 수립

**상표 (상표법):**
- 상표 등록 현황 확인 (류별 분류)
- 유사 상표 침해 가능성 검토
- 해외 상표 등록 우선순위 (PCT, 마드리드 의정서)

**저작권 (저작권법):**
- 소프트웨어·콘텐츠 저작권 귀속 확인
- 오픈소스 라이선스 컴플라이언스 (GPL, MIT, Apache)
- AI 생성물 저작권 귀속 문제 (2026년 현재 법적 불확실성 높음)

**영업비밀 (부정경쟁방지법):**
- 영업비밀 3요소 충족 여부: 비공지성 + 경제적 유용성 + 비밀관리성
- 퇴직자 영업비밀 유출 방지 체계
- 비밀관리 조치 현황 (접근 권한, 보안 서약서, 암호화 등)

### 5단계: 법적 리스크 보고서 생성

```
# 법적 리스크 평가 보고서

## 종합 리스크 현황
- 고위험: X건
- 중위험: X건
- 저위험: X건

## 2026년 법령 변화 영향 분석

## 리스크별 상세 분석 및 대응 방안

## IP 포트폴리오 현황

## 즉시 조치 필요 항목

## 6개월 이내 조치 계획
```

## 사용 예시

**예시 1**: "IT 스타트업 개인정보·노동·IP 법적 리스크 전체 점검해줘"
→ 도메인 식별 → 리스크 매트릭스 → 2026 법령 변화 영향 → 우선순위 액션 플랜

**예시 2**: "우리 서비스에 사용한 오픈소스 라이선스 컴플라이언스 위험 분석해줘"
→ 라이선스 유형 분류 → 의무사항 체크 → 위반 리스크 평가 → 대응 방안

**예시 3**: "경쟁사 특허 침해 위험 분석해줘"
→ 특허 검색 → 기술 대비 → 침해 리스크 → 설계 변경 또는 라이선스 협상

## 산출물

- IP 포트폴리오 현황 및 갭 분석
- 리스크별 대응 액션 플랜

## 주의사항

**면책 고지: AI 보조 분석이며 전문 법률 자문을 대체하지 않습니다**

**주요 법령 정보 소스:**
- 국가법령정보센터 (law.go.kr)
- 개인정보보호위원회 (pipc.go.kr)
- 특허정보검색서비스 KIPRIS (kipris.or.kr)
- 대법원 판례검색 (glaw.scourt.go.kr)
- 고용노동부 (moel.go.kr)

**법적 리스크 대응 원칙:**
1. 리스크 조기 식별 > 사후 대응 (비용 10배 이상 차이)
2. 계약서 검토는 서명 전 반드시 진행
3. 개인정보 관련 리스크는 기술적·관리적 조치 병행
4. IP 분쟁은 초기 증거 확보가 핵심

## 문제 해결

| 상황 | 대응 |
|------|------|
| 법령 해석이 불명확한 경우 | 보수적 해석 기준으로 분석. 주무 기관 유권해석 또는 법무팀 확인 권고 |
| 회사 내부 정보가 없는 경우 | 업종·규모 기반 일반적 리스크 지도 제공 후 맞춤 정보 추가 요청 |
| 최신 판례가 필요한 경우 | 대법원 판례검색 안내. 중요 사안은 법무법인 자문 권고 |

**AI 보조 분석이며 전문 법률 자문을 대체하지 않습니다**

### 후처리 체인 (텍스트 산출물)

법적 리스크 평가 보고서·법령 변화 영향 분석·대응 액션 플랜 등 서술형 산출물은 작성 후 반드시 다음 체인으로 마무리합니다.

```
legal-risk → sz:ai-slop-reviewer → sz:humanize-korean
```

- **sz:ai-slop-reviewer**: AI 글쓰기 패턴(과장·상투구·획일적 구조) 검수
- **sz:humanize-korean**: 한국어 자연스러움 보정으로 사람이 쓴 듯한 문장으로 다듬기

리스크 매트릭스 표 등 데이터 산출물은 이 체인 대상이 아니며, 별도로 **sz:xlsx-creator**로 정리합니다.

## 법률 인용 5규칙 (HARD — v1.7.2 디벨롭)

정본: `sz:contract-review`의 `references/legal-citation-rules.md`. 요약:
1. 법적 판단 문장마다 근거 조문 병기(법령명 원어 병기)
2. 말미에 출처 리스트 + 실제 링크(law.go.kr·lex.uz 등)
3. 훈련 지식으로 조문 단정 금지 — 조회로 현행성 검증, 인용은 VERIFIED/SECONDARY/NOT_FOUND/MISMATCH **4분류**(v1.7.2 개정 — SECONDARY=2차 출처로 확인·원문 미대조, `⚠ 원문 재확인 필요` 병기 / NOT_FOUND는 산출물에서 제거)
4. 개정 동향 블록: [현행 → 개정 논의 → 진행 단계 → 예상 시행], 없으면 "개정 논의 없음(조사일 기준)" 명시
5. 추정/확인 구분 표기 + 중요 사안 비변호사 고지

**관할 프로필**: 한국 질의 = korean-law MCP(미연결 시 law.go.kr) 1순위 / UZ 질의 = lex.uz·regulation.gov.uz·norma.uz 1순위. 관할 혼재 시 관할별 섹션 분리.

**정보원 접근 상한 (HARD — v1.7.2)**: lex.uz는 조문 본문이 JavaScript로 렌더링되어 자동 fetch로는 목차만 회수된다. 원문 확보 시도는 **정보원 3곳·총 5회**까지만 하고, 초과 시 즉시 2차 출처(norma·kadrovik·buxgalter)로 전환해 SECONDARY로 표기하고 진행한다. PDF 엔드포인트 추측·미러·언어판 순회는 금지. 상세는 `sz:contract-review`의 `references/source-access-notes.md`.

## 개정 동향 조사 의무 (HARD — v1.7.2 디벨롭)

리스크 평가에는 "이 규제가 지금 바뀌는 중인가"를 **항상** 포함한다:
- 사안 관련 핵심 법령마다 개정 동향 블록 작성: [현행 → 개정 논의(발의·입법예고) → 진행 단계(심의 등) → 예상 시행(확인된 경우)]
- 확인 안 되면 "개정 논의 없음(조사일 기준)" 명시 — 조사일을 반드시 기록
- 개정 진행 중인 법령 관련 리스크는 위험도 평가에 "규제 변동 리스크"를 별도 행으로 추가


## 조사 심도·소요 사전 고지 (HARD — v1.7.2 디벨롭)

정본: `sz:contract-review`의 `references/research-depth-modes.md`. 조사 착수 전 심도를 정한다.

| 모드 | 트리거 | 방식 | 예상 소요 | 허용 인용 등급 |
|---|---|---|---|---|
| ⚡ Quick(1차 답변) | "빠르게", "1차 답변만", "간단히" | 서브에이전트 위임 없이 메인에서 검색 5~6회 | 3~5분 | SECONDARY 허용 |
| ◐ Standard(기본값) | 지정 없음 | 2차 출처 중심 + 핵심 조문만 원문 시도 | 8~12분 | VERIFIED+SECONDARY |
| ◆ Deep(원문 대조) | "원문 대조", "조문 확인", 서명·분쟁 확정 사안 | 관할 1순위 원문 전수 대조 | 20분+ | VERIFIED 전용 |

- **사전 고지(HARD)**: 예상 8분 초과 또는 서브에이전트 위임·3단계 이상 체인이 필요하면 **착수 전 1회** 예상 소요와 3모드를 제시하고 선택을 받는다. 응답이 없으면 Standard로 진행하고 산출물 머리에 모드를 표기한다. 무인·예약 실행에서는 묻지 않고 Standard.
- **중단 규칙**: 원문 확보 실패가 누적되거나 재시도 상한에 도달하면 **작업을 멈추고 현재까지의 결과로 답한 뒤** 승격 여부를 묻는다.
- **문서 체인 분리(HARD)**: 조사+문서를 함께 요청받으면 ①조사 답변 확정 → ②"이 내용으로 DOCX만" 지시 시 뒷단(docx-generator → ai-slop-reviewer → humanize-korean)만 실행하는 2단 분리를 먼저 제안한다. 5단 순차 체인은 조사보다 오래 걸린다.
- 산출물 머리에 `조사 모드: …(YYYY-MM-DD 조회)` 1줄을 남긴다.

# NLP 텍스트 측정 quagmire 경보 (NLP Measurement Quagmire)

> 사업보고서·공시·뉴스 등 텍스트에서 **구성개념(construct)을 측정**하려 할 때 반복되는 함정과 처방. "측정이 quagmire면 보류"가 원칙 — 억지 측정으로 논문을 끌고 가면 심사에서 무너진다.

## 핵심 딜레마: 사전(dictionary)의 신호 vs 타당도 트레이드오프

- **타당한(특화) 사전은 신호가 희박** — 개념에 딱 맞는 특화어는 문서 출현율 낮고(예: 36%), 중앙값 0·추세 없음.
- **강한 신호는 무효** — 범용어는 대부분 문서에 등장(예: 93%)해 **우상향 착시**를 만든다. PoC의 "강한 신호"가 범용어發이면 함정.

> 판정: 초기 PoC에서 신호가 강하면 **그 신호가 특화어에서 나왔는지 범용어에서 나왔는지** 반드시 분해하라.

## 길이 정규화 함정

전체 XML(표·주석 포함, 예: 1.7MB)로 나누면 서사 섹션의 신호가 **희석**된다.
→ **'사업의 내용'·'위험요인' 등 서사 섹션만 추출** 후 측정.

## 처방: 수렴타당도 없으면 게재 불가

```
dictionary 초벌
  → 섹션 추출(서사부만)
  → 임베딩(KR-BERT 등) 측정 병행
  → 외부지수(예: GPR 지정학위험지수)와 수렴타당도(convergent validity) 확인
```
셋(사전·임베딩·외부지수)이 수렴하지 않으면 **측정 실패 → 보류**. 소표본 코퍼스(수백 사)도 병목이 된다.

## 코퍼스 자산 재사용

이미 구축한 텍스트 코퍼스(예: 사업보고서 전문 다년치)는 **신규 텍스트 주제의 1차 확인처**. 새 텍스트 주제 착수 시 기존 코퍼스에서 base rate·신호부터 확인(→ `sandbox-execution-patterns.md`, `data-pipeline-traps.md`).

## 경보 체크리스트

```
[ ] 강한 신호가 특화어發인가 범용어發인가 분해했는가
[ ] 서사 섹션만 추출해 길이 정규화 희석을 피했는가
[ ] 사전·임베딩·외부지수 수렴타당도를 확인했는가
[ ] 코퍼스 규모가 검정력에 충분한가 (수백 사면 병목 경고)
[ ] 위 미충족이면 "보류" 판정하고 다른 측정/주제로 전환했는가
```

## 검증(정밀도/재현율)

규칙·사전 추출 결과는 **N=300 층화 라벨링**으로 정밀도·재현율·κ 산출. LLM 보조 라벨 + 사람 스팟체크 하이브리드 허용.

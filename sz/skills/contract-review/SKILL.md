# 계약서 검토 (Contract Review)

## 개요

계약서 검토 및 법률 문서 작성을 지원한다. 한국 민법·상법 기준 계약서 10대 리스크 패턴 분석, 이용약관·개인정보처리방침·SLA 작성, 2026년 개정 개인정보보호법 반영, 불리한 조항 수정 권고안을 제공한다.

**면책 고지: AI 보조 분석이며 전문 법률 자문을 대체하지 않습니다**

## 트리거 키워드

계약서, 계약 검토, 위험 조항, 이용약관, 개인정보처리방침, SLA, 민법, 상법, 법률 문서, 용역계약, 공급계약, 파트너십 계약, 협약서

## 워크플로우

### 1단계: 요청 유형 확인

**작업 유형:**
- **계약서 검토**: 기존 계약서의 위험 조항 분석 및 수정 권고
- **법률 문서 작성**: 이용약관, 개인정보처리방침, SLA 등 신규 작성

**문서 유형:**
- 용역계약 (SI, 개발 외주, 컨설팅)
- 공급계약 (제품, 소프트웨어 라이선스)
- NDA (비밀유지계약)
- 파트너십·제휴 계약
- 이용약관, 개인정보처리방침, SLA

**한국법 또는 외국법 적용 여부 확인**

### 2단계: 계약서 검토 (10대 리스크 체크)

**① 계약 당사자 정보 정확성**
- [ ] 상호명, 사업자등록번호, 대표자, 주소 확인
- [ ] 계약 당사자의 권한 범위 (대표이사·대리인 확인)

**② 계약 목적 및 범위 명확성**
- [ ] 용역·공급의 대상과 범위가 구체적일까?
- [ ] 성과물의 명세 ( Deliverables )가 명시되어 있을까?

**③ 대금·지급 조건 및 지연 이자**
- [ ] 계약금·중도금·잔금 지급 일정
- [ ] 지급 조건 (검수·승인 후 지급 등)
- [ ] 지연 이자율 (연 20% 법정 최고금리 이내 권장)

**④ 납기·이행 조건 및 위약 조항**
- [ ] 납품·완료 기일이 명확한가?
- [ ] 지연 시 위약벌(손해배상 예정)이 합리적인가?
- [ ] 불가항력(Force Majeure) 조항 포함 여부

**⑤ 지적재산권 귀속**
- [ ] 성과물의 지적재산권(특허, 저작권, 영업비밀) 귀속
- [ ] 기존 IP와 신규 IP의 구분
- [ ] 라이선스 범위(독점·비독점)

**⑥ 비밀유지 조항**
- [ ] 비밀정보의 정의와 범위
- [ ] 비밀유지 의무 기간 (일반: 2-5년, 영업비밀: 영구도 가능)
- [ ] 예외 조항 (공지 정보, 독자 개발, 제3자 취득, 법령 공개)

**⑦ 손해배상 범위 및 한도**
- [ ] 직접 손해 vs 간접 손해(특별 손해)
- [ ] 손해배상 한도 설정 (예: 계약금 총액의 100%)
- [ ] 특약사항(면책 조항)

**⑧ 계약 해지 조건 및 효과**
- [ ] 사전 해지 통지 기간 (통상 30일)
- [ ] 해지 사유 (사안, 쌍방 해지 권한)
- [ ] 해지 시 효과 (비용 정산, 성과물 반환)

**⑨ 분쟁 해결 (관할 법원, 준거법, 중재)**
- [ ] 합의 관할 법원 (당사자 일방所在地 법원 권장)
- [ ] 준거법 (한국법 적용 명시 권고)
- [ ] 조정·중재 조항 (선택 사항)

**⑩ 불공정 조항 (약관법 위반 가능성)**
- [ ] 고객에게 부당하게 불리한 조항
- [ ] 고객의 권리를 제한하는 조항
- [ ] 면책 조항의 과도한 제한

### 3단계: 법률 문서 작성 (선택)

**이용약관:**
- 전자상거래법·소비자보호법 준수
- 필수 포함 사항:
  - 서비스의 이용 방법과 이용 조건
  - 이용 요금 및 결제 방법
  - 이용 제한 및 해지 절차
  - 책임 한계 (면책 조항)
  - 분쟁 해결 (관할 법원 등)

**개인정보처리방침:**
- 개인정보보호법 (2026.9.11. 개정) 반영
- 필수 포함 사항:
  - 수집 항목 (필수·선택)
  - 이용 목적
  - 보유 기간
  - 제3자 제공 (유무, 대상, 목적)
  - 파기 방법 및 절차
  - 정보주체의 권리 (열람, 정정, 삭제)
  - 쿠키 사용 여부

**SLA (Service Level Agreement):**
- 가용성 목표 (예: 99.9% 업타임)
- 장애 등급별 대응 시간 (P1/P2/P3)
- 위반 시 보상 방법 (서비스 크레딧, 위약벌)
- 모니터링·보고 방법

### 4단계: 수정 권고안 제시

**리스크 조항 표시 및 대안 문구 제안:**
- 🔴 **즉시 수정 권고**: 법적으로 명백히 불리한 조항
- 🟡 **협상 권고**: 합의 가능한 조항
- 🟢 **수용 가능**: 일반적인 수준의 조항

**협상 포인트 우선순위:**
1. 지적재산권 귀속 (성과물 IP 소유)
2. 손해배상 한도 (무제한 책임 방지)
3. 계약 해지 조건 (불리한 해지 방지)
4. 관할 법원 (원거리 법원 방지)

## 법률 인용 5규칙 (HARD — v1.7.2 디벨롭)

정본: `sz:contract-review`의 `references/legal-citation-rules.md`. 요약:
1. 법적 판단 문장마다 근거 조문 병기(법령명 원어 병기)
2. 말미에 출처 리스트 + 실제 링크(law.go.kr·lex.uz 등)
3. 훈련 지식으로 조문 단정 금지 — 조회로 현행성 검증, 인용은 VERIFIED/SECONDARY/NOT_FOUND/MISMATCH **4분류**(v1.7.2 개정 — SECONDARY=2차 출처로 확인·원문 미대조, `⚠ 원문 재확인 필요` 병기 / NOT_FOUND는 산출물에서 제거)
4. 개정 동향 블록: [현행 → 개정 논의 → 진행 단계 → 예상 시행], 없으면 "개정 논의 없음(조사일 기준)" 명시
5. 추정/확인 구분 표기 + 중요 사안 비변호사 고지

**관할 프로필**: 한국 질의 = korean-law MCP(미연결 시 law.go.kr) 1순위 / UZ 질의 = lex.uz·regulation.gov.uz·norma.uz 1순위. 관할 혼재 시 관할별 섹션 분리.

**정보원 접근 상한 (HARD — v1.7.2)**: lex.uz는 조문 본문이 JavaScript로 렌더링되어 자동 fetch로는 목차만 회수된다. 원문 확보 시도는 **정보원 3곳·총 5회**까지만 하고, 초과 시 즉시 2차 출처(norma·kadrovik·buxgalter)로 전환해 SECONDARY로 표기하고 진행한다. PDF 엔드포인트 추측·미러·언어판 순회는 금지. 상세는 `sz:contract-review`의 `references/source-access-notes.md`.

## 검토 표준 출력 (HARD — v1.7.2 디벨롭)

검토 모드 산출물은 다음 구조를 따른다:
1. **유형 판별 → 프리셋 적용** — `references/contract-presets.md`에서 계약 유형(용역·공급/매매·투자·근로·라이선스)을 판별해 해당 체크포인트를 기본 검토 축으로 사용. 사용자가 "프리셋 사례로 추가해줘"라고 하면 해당 유형의 축적 사례에 3줄 형식(계약 개요·쟁점→처리·교훈)으로 append.
2. **조항별 위험도 매트릭스** — 각 쟁점 조항을 [높음🔴/중간🟡/낮음🟢] 3등급 + 근거 1줄로 표 정리.
3. **수정 문안 3단 제안** — 위험도 높음·중간 조항에는 수정안을 [보수(상대 수용 용이)/균형(권장)/공격(자사 최대 보호)] 3단으로 제시.
4. **반론 검증 체이닝** — 검토 완료 후 `sz:devil-review`로 "이 검토가 놓친 리스크·과잉 지적"을 1회 교차 검증하고 결과를 반영.
5. **문서화** — 검토의견서 요청 시 `sz:docx-generator` 또는 `sz:html-report` 체인(디자인 게이트 적용). 마감은 ai-slop-reviewer → humanize-korean.


## 조사 심도·소요 사전 고지 (HARD — v1.7.2 디벨롭)

정본: `sz:contract-review`의 `references/research-depth-modes.md`. 조사 착수 전 심도를 정한다.

| 모드 | 트리거 | 방식 | 예상 소요 | 허용 인용 등급 |
|---|---|---|---|---|
| ⚡ Quick(1차 답변) | "빠르게", "1차 답변만", "간단히" | 서브에이전트 위임 없이 메인에서 검색 5~6회 | 3~5분 | SECONDARY 허용 |
| ◐ Standard(기본값) | 지정 없음 | 2차 출처 중심 + 핵심 조문만 원문 시도 | 8~12분 | VERIFIED+SECONDARY |
| ◆ Deep(원문 대조) | "원문 대조", "조문 확인", 서명·분쟁 확정 사안 | 관할 1순위 원문 전수 대조 | 20분+ | VERIFIED 전용 |

- **사전 고지(HARD)**: 예상 8분 초과 또는 서브에이전트 위임·3단계 이상 체인이 필요하면 **착수 전 1회** 예상 소요와 3모드를 제시하고 선택을 받는다. 응답이 없으면 Standard로 진행하고 산출물 머리에 모드를 표기한다. 무인·예약 실행에서는 묻지 않고 Standard.
- **중단 규칙**: 원문 확보 실패가 누적되거나 재시도 상한에 도달하면 **작업을 멈추고 현재까지의 결과로 답한 뒤** 승격 여부를 묻는다.
- **문서 체인 분리(HARD)**: 조사+문서를 함께 요청받으면 ①조사 답변 확정 → ②"이 내용으로 DOCX만" 지시 시 뒷단(docx-generator → ai-slop-reviewer → humanize-korean)만 실행하는 2단 분리를 먼저 제안한다. 5단 순차 체인은 조사보다 오래 걸린다.
- 산출물 머리에 `조사 모드: …(YYYY-MM-DD 조회)` 1줄을 남긴다.

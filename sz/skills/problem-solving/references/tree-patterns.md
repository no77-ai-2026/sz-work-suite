# 로직트리 유형·게이트·프레임워크 카탈로그 (tree-patterns)

## 1. 트리 5유형 — 가설 확신도에 따라 선택 (혼용 금지)

| 확신도 | Type | 중심 질문 | Final Node | 검증 방식 |
|---|---|---|---|---|
| 낮음 — 무엇이 벌어지는지도 모름 | **What Tree** (요소 분해) | 무엇으로 구성되는가? | 측정 가능한 변수 | 합산 검증 (합=상위) |
| 소재는 좁혔으나 원인 모름 | **Why Tree** | 왜 발생했는가? | 근본 원인(root cause) | 인과 검증 (제거 시 해소) |
| 원인은 알았으나 결정 정리 필요 | **Issue Tree** | 무엇이 쟁점이며 참인가? | Yes/No 질문 | MECE + Fork Test |
| 방향이 보임 — 반증 확인 | **Hypothesis Tree** | 이 답이 맞는가, 왜? | 논거(supporting argument) | 반증 가능성 |
| 높음 — 실행 방법 | **How Tree** | 어떻게 달성하는가? | 구체적 액션 | 실행 가능성 + 임팩트 |

보조: **Decision Tree(Option Tree)** — Yes/No 이슈·솔루션을 연속 배치해 조건 분기별 Action에 도달 (예: 자회사 처분 — 수익성 정착? → 시너지? → 매각 시 그룹 가치? → 현금흐름 위협? → 유지/매각/구조변화).

- 트리 산출 시 반드시 유형을 명시한다 (예: "Issue Tree로 분해합니다")
- So What/Why So 검증은 Why Tree에는 적합하지 않을 수 있음
- 참고 계보: Issue Tree(초기, '무엇을 볼지') → Hypothesis Tree(중기, '왜'의 논거) 전환이 문제해결 가속의 핵심

## 2. MECE 실패 3유형 (검사 시 대조)

| 실패 | 예 |
|---|---|
| ME이지만 CE 아님 (누락) | 생물 = 포유류 + 어류 |
| CE이지만 ME 아님 (중복) | 여성 = 독신녀 + 주부 + 직장여성 |
| 둘 다 아님 | 학생 = 수학 잘하는 학생 + 영어 잘하는 학생 |

MECE 절단 기준 예: 질/양, 효과성/효율성, 단기/중기/장기, 과거/현재/미래, 내부/외부, 수식 분해(매출=단가×수량).
주의: 엄밀한 MECE보다 상대에게 가치 있는 MECE. 중복 검출 예: "시장 성장?"은 "시장 매력?"의 부분집합.

## 3. Actionable·Relevant 판정

**Actionable 2기준**: (a) 데이터로 답할 수 있을 만큼 구체적인가 (b) 답이 나오면 다음 행동이 자동으로 따라오는가.
예 — "임금 인상해야 하는가?": "현 임금이 적정 수준인가?"(시장 벤치마킹→낮으면 인상 근거) / "고용·유지에 문제 있는가?"(이직률·오퍼 수락률→임금이 원인이면 해결 가능) / "인상이 생산성을 높이는가?"(ROI>0이면 투자로 정당화) — 모두 통과.

**Relevant 기준**: 하위의 답이 상위의 답에 직접 기여하는가 — 하위마다 "So what, 그래서 상위 이슈에 뭐라고 말해주는데?"를 물어 다리가 놓여야 함.
예 — "점유율 회복 위해 공장 처분?": "자금이 있는가?"(✗ 연결 끊김) / "제품 경쟁력을 높이는가?"(✓ 단, 자사 공장이 경쟁력 원천이 아닐 때만) / "원가구조를 개선하는가?"(✓ 단, 외주 단가가 자사 원가보다 저렴할 때만) — 성립 조건까지 명시할 것.

## 4. 프레임워크 카탈로그 (Force at Work 적용)

트리 분기에 검증된 프레임워크를 쓰면 절단면의 통찰이 좋아진다. 단, 칸 채우기 금지 — 도출할 결론을 염두에 둘 것. 클라이언트 상황에 맞는지 먼저 확인.

| 분기 상황 | 프레임워크 |
|---|---|
| 시장 매력도 | Porter 5 Forces (진입장벽·경쟁강도·대체재·구매자·공급자) |
| 자사 역량 | McKinsey 7S (Strategy·Structure·Systems·Shared Value·Skills·Style·Staff) |
| 거시 환경 | PEST/STEEP 계열 |
| 원인 규명 (Why 트랙) | 5 Whys, 피시본(이시카와), Kepner-Tregoe IS/IS-NOT(문제분석) |
| 리스크 예방 | KT 잠재문제분석(Potential Problem Analysis) |
| 전략 서사 검증 | Rumelt 커널 (진단→가이드 정책→일관된 행동) |
| 발산이 필요할 때 | 더블 다이아몬드(발산↔수렴), 브레인스토밍·SCAMPER |

개념 위계: Concept(관점) ⊃ Framework(구조화된 접근) ⊃ Method(단위 접근) ⊃ Tool(정의된 절차). "Framework is the way of thinking."

## 5. 예시 트리 (few-shot)

**Issue Tree — "B사는 스포츠 음료 OTC 시장에 진출해야 하는가?"**
```
├─ 사업이 B사에 적합한가? ─ Vision·목표 적합 / 기업문화 / 기존 사업 시너지 / 내부 역량(마케팅·기술·생산·인력·자금)
└─ 시장은 매력적인가? ─ 성장성 / 규모 / 경쟁 강도(5 Forces 분해)
```

**Why Tree — "그녀의 요리 솜씨를 개선할 수 있나?"**: 자질(의욕·기술) vs 자질 외(시간·설비)로 원인 분해.

**How Tree — "요리 문제를 해소해 결혼에 성공할까?"**: 개별이슈 해결(학원·귀가시간 변경·저녁 지연) vs 종합 해결(자기노력·타력이용) — 말단은 전부 실행 가능한 액션.

**What Tree — "그녀는 매력적인가?"**: 외관(전체/부분) + 내면(라이프스타일/자질) + 본인 외(가족·친척/친구) — 말단은 측정·관찰 가능한 요소.

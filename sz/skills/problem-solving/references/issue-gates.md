# 이슈 판정 게이트 (issue-gates)

## 1. 3-Test 판정표 (이슈 후보마다 필수 적용)

| 테스트 | 질문 | 미달 시 조치 |
|---|---|---|
| **Fact Test** | 검증 가능한 문제적 사실이 문장에 들어 있는가 | 진단 데이터에서 사실을 찾아 삽입. 미확인이면 [추정] 표기 + 검증 목록 이관 |
| **Fork Test** | 답이 대안 간 선택으로 떨어지는가 | "~해야 하는가"가 사실상 대안 1개면, 경쟁하는 두 대안이 대립하도록 재작성 |
| **Action Test** | 답이 나오면 곧바로 무엇을 할지 결정되는가 | stake(무엇이 걸려 있는지)와 트레이드오프를 문장에 삽입 |

출력 형식: 이슈 3안 각각에 3-Test 통과 여부 표 + 미달 항목은 사유 1줄.

## 2. 이슈 판정 예시 (좋은/나쁜)

| 후보 | 판정 |
|---|---|
| "자회사의 수익이 2020년에 20% 감소" | ✗ 사실적 정보 |
| "자회사의 수익성이 향상될 수 있는가?" | ✗ 논쟁의 여지가 없는 given situation |
| "왜 수익이 20%나 감소했는가?" | ✗ 분석이 용이하지 않은 열린 질문 (Why Tree 트랙으로) |
| "2027년에는 수익 감소를 면할 수 있는가?" | ✓ Yes/No 대답 가능 |
| "제조비용 감소로 수익성이 개선될 수 있는가?" | ✓ 전략 옵션·권고 도출 가능한 Sub-Issue |

## 3. 열린 질문의 이슈화 패턴

| 열린 질문 | 결함 | 이슈화 (예시) |
|---|---|---|
| "필요한 재고 수준은?" | 방향·판단 기준 없음 | "재고 4.5개월치로 업계 평균(2개월)의 2배 이상, 연간 XX억 운전자본 비용을 유발하는 상황에서, 납기충족률 95%를 유지하며 재고를 2개월치로 감축해야 하는가?" |
| "공장을 어떻게 해야 하나?" | "어떻게"형 — 무한 해석 | "3년째 가동률 60%로 손익분기(75%)를 하회하며 연 XX억 고정비 손실을 내는 A공장을 폐쇄·B공장 통합해야 하는가, 유지하며 신규 수주로 가동률을 회복해야 하는가?" |
| "기술을 JV에 전수해야 하는가?" | Yes/No지만 사실·stake 부재 | 문제적 사실(예: 기술 유출 리스크 vs 시장 접근 가치)과 트레이드오프를 삽입해 재작성 |

## 4. 추정형 질문 처리 규칙

**추정형 질문(가치·규모·전망)은 이슈가 아니라 분석 과제다. 의사결정 기준(hurdle)과 결합해야 이슈가 된다.**

절차: ① 이 추정이 어떤 의사결정 때문에 필요한지 맥락 복원 (가치평가는 항상 딜 때문에, 매출 추정은 출시·투자 결정 때문에 수행됨) → ② hurdle을 찾거나 사용자에게 확인 → ③ 표준 문형으로 재작성.

예시: "파이프라인 가치는 얼마인가?" → "라이선서가 총 X억을 요구하는 상황에서, PoS·경쟁 구도를 반영한 rNPV가 요구 대가를 상회하여 현 조건으로 계약해야 하는가, 아니면 upfront를 낮추는 구조로 재협상해야 하는가?"
예시: "시장 전망과 매출 추정은?" → 두 분석 과제의 나열 + 비MECE. 투자 정당화 기준(peak sales 연 Y억)과 결합해 "자체 출시 vs 파트너십" 갈림길로 재작성.

## 5. 가설 QDT (Quick and Dirty Test)

가설마다 2질문: ① 이 가설이 사실이 되려면 어떤 전제가 있어야 하는가? ② 이 가설을 틀리게 할 요인은 무엇인가?
전제에 문제가 있거나 가능성이 낮으면 좋은 가설이 아님 — 재작성. 가설은 반증 가능(falsifiable)해야 한다.

## 6. 이슈 선별 우선순위 (80:20)

이슈 3안 중 진행할 안의 선택 기준: 결과에 미치는 임팩트 × 분석 가능성. 임팩트가 작거나 분석 불가능한 안은 가지치기하고 사유를 1줄 기록한다. **선택은 사용자(사람)에게 확인받는다.**

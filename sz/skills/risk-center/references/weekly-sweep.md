## 검증 (HARD)
- 신규·변경 인용 URL은 **개별 WebFetch 전수검증**(라이브·내용 일치·발표일=게시일 확인).
- 1차 출처 재확인 실패 시 '잠정' 강등(SECONDARY, ⚠ 병기). 결과는 `03_검증로그/`에 축·카테고리별 쿼리·결과 기록.
- 갱신 후 대시보드 반영 대상: 데이터(RISK_DATA·KPIS·BW) + 홈 `WTO_EVENTS` + 각 뷰 스냅샷 날짜 + 우상단 최종 업데이트·버전 + **`SNAPSHOT_DATE`**.

## 갱신 체크리스트 (매 주기 필수)
- [ ] 프로젝트 루트에 `_반영준비_*` 문서가 있으면 먼저 확인·반영 후 `03_검증로그/`로 이동
- [ ] 신규·변경 항목의 날짜가 **1차 출처 공식 발표일** 기준인지 확인
- [ ] `SNAPSHOT_DATE`를 새 기준일로 갱신(최근 3주 배지 정합)
- [ ] 버전·파일명·우상단 날짜·각 뷰 스냅샷 표기 일괄 동기화 후 **치환 오염 여부 검증**(과거 사례: 한 뷰의 '다음 갱신' 날짜 치환이 셸 헤더까지 변경)
- [ ] 렌더링 검증(항목 수·패널·EN 전환·배지·CSS 폴백) 후 검증 로그 발행
- [ ] 샘플(`SAMPLE-`) 항목 잔존 0

체인: 전수 스윕 → 카테고리 큐레이션·등급 판정(`sz:risk-radar`) → 대시보드 HTML 갱신(새 파일명) → URL 전수검증 → `sz:validate-data` QA → 검증 로그 발행 → **한국어 델타 브리핑 6항목**.

## 최근 3주 배지 구현
운영 리스크 항목 카드는 스냅샷 기준일로부터 21일 이내 1차 발표·보도가 있으면 자동 표시.
- 판정: 항목의 `last` 또는 `sources[].date` 최댓값이 `SNAPSHOT_DATE − RECENT_DAYS(21)` 이후
- 표시: 카드 `최근 3주`(EN `Last 3 wks`) 배지 + 좌측 컬러 바, 카테고리 헤더 건수 배지
- 구현: OPS 모듈 `SNAPSHOT_DATE`·`RECENT_DAYS` 상수와 `isRecent()`·`latestSourceDate()` — **주간 갱신 시 `SNAPSHOT_DATE` 반드시 동기화**

## 텍스트 렌더링 규칙
- HTML 태그(`<b>` 등)를 포함하는 i18n 문자열(`latest_signal_val`, BW `auditNote`·`tariffNote`·`footer` 등)은 **innerHTML**로 주입 — `data-i18n-html` 속성 또는 렌더러 예외 목록. `textContent`로 넣으면 태그가 문자로 노출.
- 태그 없는 일반 라벨은 `textContent`. 신규 문자열 추가 시 태그 포함 여부를 확인.

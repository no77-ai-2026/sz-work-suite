# router.md — project 스킬 라우팅 프로토콜 (플러그인 패밀리, 전 코워커)

## 개요

사용자의 자연어 요청을 분석해 project 스킬이 다룰 **SZ 플러그인(sz 코어 / sz-creative / sz-commerce)** 중 어느 스킬 체인이 중심이 될지 결정하는 프로토콜. 개발 프로젝트 초기화는 범위 밖이다. 스킬 수는 하드코딩하지 않는다 — 각 번들 `plugin.json`+skills/ 실측이 로스터 정본이다.

---

## 1. 라우팅 흐름

```
사용자 자연어 요청 (/work 진입)
    ↓
[1단계] 프로젝트 컨텍스트 확인 — AGENTS.md "프로젝트 워크플로우"에 이미 정의된 체인 있음 → 직접 실행
    ↓ (없으면)
[2단계] 코워커 키워드 매핑 → 중심 코워커·스킬 체인 결정
    ├── 매칭 1개 코워커 → 해당 코워커 중심 설계
    ├── 매칭 2개+ → §2 모호성 해소 / §3 복합 요청
    └── 매칭 0개 → §4 폴백
```

## 3. 모호성 해소

키워드 매칭 결과 중심 코워커 후보가 2개 이상일 때:

- **자동 해소**: 산출물 유형이 명시되면 해당 산출물을 만드는 코워커 우선. 예: "브랜드 카드뉴스 만들어줘" → 콘텐츠 산출물 명시 → 마케터 중심.
- **사용자 확인**: 자동 해소가 어려우면 `AskUserQuestion`(1질문, 후보 코워커 최대 4개 + Other).

## 4. 복합 요청 처리 (크로스 코워커)

요청이 여러 코워커에 걸치면 **하나의 `AGENTS.md` 워크플로우 표에 코워커별 체인을 함께 설계**하고, 반복 작업 유형별 커스텀 에이전트가 체인을 호출하도록 배선한다.

```
"스타트업이라 사업계획서랑 웹사이트 디자인 둘 다 필요해"
→ /work 1회 셋업:
   워크플로우 표 = 코워커(사업계획서 체인) + 디자이너(브랜드 셋업 체인)
   커스텀 에이전트 = biz-plan-writer, brand-system-keeper
```

개발이 섞이면(`"서비스 개발도 해야 해"`) → 개발 환경 셋업은 이 마켓플레이스의 범위 밖임을 안내하고, 비개발 영역(기획·콘텐츠·디자인)만 설계한다.

**심층 분석 판단**: 복합 요청이거나 3개+ 코워커 체인이 걸치면 `ultrathink`(심층 분석)로 최적 설계를 결정한다.

## 5. 폴백 전략

| 상황 | 대응 |
|------|------|
| 키워드 매칭 0개 | 기본 코워커 제안 후 확인(대다수 사용자) |
| 중심 코워커 미설치 | Gap Detection → 설치 안내 → "이어서 진행" 재개 |
| 개발 환경 셋업 요청 | 이 마켓플레이스 범위 밖임을 안내하고 비개발 영역만 설계 |

---

## 6. 검증 깊이 연동

라우팅과 함께 **검증 깊이 등급**도 정한다(상세: `execution-protocol.md`):

- 법률·계약·개인정보·세무·재무·정부지원·의료·규제 키워드, 또는 2개+ 코워커 체인 → **DEEP**
- 일반 산출물(보고서·카피·문서) → **NORMAL**
- 단순 조회·요약 → **QUICK**

키워드는 seed일 뿐이며, 트리거 단어 없이 표현된 고위험 요청도 맥락으로 DEEP 판단한다.

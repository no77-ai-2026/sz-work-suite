# common-rules — 전 프로젝트 공통 HARD 규칙 (플러그인 SSOT)

> **타 번들 연계**: 본 문서의 `sz:*`·`sz:*` 참조는 해당 번들이 설치된 경우에만 체이닝합니다. 미설치 시 해당 단계를 생략하고 코어 스킬만으로 진행합니다.


> **이 파일이 공통 규칙의 정본이다.** `/project`가 생성하는 각 프로젝트 `AGENTS.md`는 이 파일을 복제하지 않고 1줄로 참조한다("공통 HARD 규칙은 sz:work `references/core/common-rules.md` 정본을 따른다"). 규칙 개정은 이 파일 한 곳에서만 한다 — 33개+ 프로젝트 지침이 동시에 낡는 문제(지침 노화)를 차단하는 2층 구조의 아래층이다.

---

## 1. 산출물 등급제 (HARD — 체인·포맷 공통 기준)

모든 텍스트 산출물은 3등급 중 하나로 생성한다. **기본값은 ⚡초안**이다 — 사용자가 명시하지 않으면 검수 체인을 돌리지 않는다.

| 등급 | 트리거 | 검수 체인 | 기본 포맷 |
|------|--------|-----------|-----------|
| **⚡ 초안** (기본값) | 별도 지시 없음 | 없음 — 생성 스킬만 실행 | 채팅 답변 또는 .md |
| **◐ 작업본** | "작업본", "다듬어서", "검수해서" | `sz:ai-slop-reviewer` 1회 | .md / .html |
| **◆ 최종본** | "최종", "납품", "발행", "제출용" 명시 시**만** | 풀 체인: `sz:ai-slop-reviewer` → `sz:humanize-korean` → `sz:korean-spell-check` + 3중 QA(사실 검증·형식 검증·요구사항 대조) | 프로젝트 기본 포맷(§AGENTS.md 지정 — docx/hwpx/pptx 등) |

- 사용자가 포맷을 명시하면 등급 기본 포맷보다 우선한다(오버라이드).
- 상위 등급 승격은 언제든 가능하다("이거 최종본으로 올려줘" → 기존 초안에 풀 체인 적용).
- 비텍스트 산출물(차트·표·숫자 리포트·코드·이미지)은 등급제 검수 체인을 적용하지 않는다.

## 2. 행동 원칙 (HARD)

1. **사전 확인 후 실행**: 맥락·목적·독자·양식을 확인한 뒤 착수한다.
2. **멀티스텝 작업은 체인 보고 후 실행**: ◐·◆ 등급 또는 2스킬 이상 체인은 계획을 먼저 보고하고 AskUserQuestion으로 승인받는다. ⚡초안 단일 스킬은 바로 실행한다.
3. **검증되지 않은 완료 주장 금지**: 출처 미확보 수치·미확인 사실·외부 입력 대기 항목은 산출물 끝 「확인 필요 항목」으로 모아 명시한다. 검증을 못 끝냈으면 끝낸 척하지 말고 무엇이 왜 막혔는지 적는다. "작성하겠습니다"라고 말한 작업은 그 응답 안에서 수행한다.
4. **타 번들 참조는 설치 시에만 체이닝**: 미설치 번들의 스킬이 체인에 있으면 해당 단계를 생략하고 1줄로 알린다.

## 3. 요청 평가 사다리 (HARD)

모든 요청은 아래 3단계를 순서대로 판단하고, 충분한 가장 가벼운 단계에서 멈춘다.

1. **대화형 답변으로 충분한가** → 프로즈로 답하고 종료 (체인 미기동)
2. **설치된 스킬·도구가 범주에 맞는가** → 해당 스킬을 등급제 기준으로 실행
3. **파일 산출물 신호가 있는가** ("파일로 줘", 오피스 포맷 지정, 독립 산출물 요청) → 파일 생성

어느 단계를 왜 골랐는지는 서술하지 않는다 — 조용히 선택하고 산출한다.

## 4. 파일 생성 기준 (HARD)

- **파일로 만든다**: 독립 산출물(보고서·계약서 초안·기획서), 오피스 포맷 요청, 대화 밖 사용·수정 반복 예정 산출물
- **대화로 답한다**: 지식 질문, 짧은 목록·표, 간단한 설명, 조회·요약
- **장문은 일괄 생성하지 않는다**: 개요 → 섹션별 작성 → 검토 → 마무리 순 반복 생성. 단문은 한 번에.

## 5. 문서·콘텐츠 생성 우선순위 (HARD)

설치된 번들에 해당 스킬이 있으면 Claude 기본 도구 대신 스킬을 사용한다.

| 산출물 | 사용 스킬 | 번들 |
|---|---|---|
| DOCX / PPTX / XLSX / HWPX / PDF | `sz:docx-generator` / `sz:pptx-designer` / `sz:xlsx-creator` / `sz:hwpx-writer` / `sz:pdf-writer` | sz |
| HTML 보고서 / 슬라이드 | `sz:html-report` / `sz:html-slide` | sz |
| 블로그 / 카드뉴스 / 뉴스레터 / SNS / 카피 | `sz:blog` / `card-news` / `newsletter` / `sns-content` / `copywriting` | sz-creative |
| 랜딩 페이지 | `sz:landing-page` | sz-creative |
| 이미지 / 영상 / 음성 | `higgsfield-image(미포함)` / `higgsfield-video` / `audio-gen` | sz-creative |
| 상세페이지 | `sz:detail-page-copy`(카피) · `detail-page-image`(이미지) | sz-commerce |

## 6. AI 슬롭 후처리 (HARD — 등급제 연동)

후처리 체인은 §1 등급제가 결정한다. **⚡초안은 후처리 없음**, ◐작업본은 `sz:ai-slop-reviewer` 1회, ◆최종본만 풀 체인(`ai-slop-reviewer` → `humanize-korean` → `korean-spell-check`)이다. 과거의 "모든 텍스트 산출물 무조건 풀 체인" 규칙은 폐기한다.

- 검수 출력: **진단 요약 → 수정 텍스트 → 주요 변경사항** 3블록
- 제외: 코드, JSON/CSV, 차트·표, 숫자 리포트, 단순 조회 응답

## 7. 인용·저작권 가드 (HARD)

- 직접 인용은 원문 **15단어 미만**, 출처당 **최대 1회**
- 가사·시는 한 줄도 전문 재현하지 않는다
- 원문 소비를 대체하는 요약(구조·서사 흐름을 그대로 따라가는 요약)을 만들지 않는다
- 기본 동작은 자기 문장으로의 **완전 재표현**
- 법무·조사 산출물의 인용 무결성 4분류(VERIFIED/SECONDARY/UNVERIFIED/MISSING)·조사 심도 3모드는 `sz:contract-review`의 `references/research-depth-modes.md`를 따른다

## 8. 톤 규칙 (HARD)

- **프로즈 기본** — 불릿·번호·볼드는 구조가 꼭 필요하거나 사용자가 요청할 때만
- **응답 깊이는 요청 깊이에 비례** — 짧은 질문에 장문 설명을 붙이지 않는다
- 불필요한 되묻기를 피한다 — 구조화 질문이 필요하면 AskUserQuestion (1라운드 4질문 이내)

## 9. 맥락 적용 규칙 (HARD)

- 프로젝트 맥락(AGENTS.md §개요 + `.sz/context.md` + 누적 노트)은 현재 요청과 관련 있을 때만 선택적으로 적용한다
- 적용할 때는 원래 알던 것처럼 자연스럽게 녹인다 — "저장된 맥락에 따르면" 같은 회수 서술 금지
- 일반 지식 질문에 프로젝트 맥락을 억지로 결부하지 않는다

## 10. 장시간 작업 사전 고지 (HARD)

예상 소요 **8분 초과** 또는 서브에이전트 위임·3단계 이상 체인 작업은 착수 전 예상 소요와 대안(빠른 1차 답변/표준/전수 검증)을 1회 제시하고 사용자가 고르게 한다. 무응답·무인 실행은 중간 옵션. 조사+문서화 복합 요청은 ①조사 확정 → ②문서화 2단 분리를 먼저 제안한다.

# research-verify — 하네스형 리서치 실행·검증 스킬

## 스킬 개요(상세)

"AI 초안은 검증 전 문서다"라는 원칙 위에서, 리서치를 **수집 → 검증 → 반론 → 조건부 결론**의 루프로 수행한다. 모든 수치에 출처를 병기하고 확인 불가 정보에 [미검증] 태그를 붙이며, 팩트·출처·논리 3관점 검증과 근거 있는 반론(Red)을 통과한 결론만 산출한다. 문제가 무엇인지 정의하는 단계는 `sz:problem-solving`이 담당하고, 이 스킬은 그 Work Plan의 Evidence 수집·검증을 실행한다. 단독 호출도 가능하다.

추가 트리거 예시: "검증된 리서치 해줘", "미검증 수치 찾아줘", "반론 돌려줘", "이 문서 팩트·출처·논리로 검증해줘", "tekshirilgan tadqiqot" (검증된 조사, UZ)

## 출력 규칙 (모든 산출물에 상시 적용)

1. 모든 정량 주장에 출처(기관·연도·링크) 병기
2. 확인 불가 정보는 본문에 **[미검증]** 태그 + 문서 말미에 미검증 항목만 모은 표
3. 내부 자료에 근거하되 추정이 섞인 내용은 **[추정]** 태그
4. 산출물 최상단에 핵심 메시지 1문장 (피라미드 구조)
5. 표로 정리 가능한 내용은 서술 대신 표 — 각 행에 근거 파일명 또는 출처 표기

## 워크플로

### 1단계. 내부 컨텍스트 우선 (파일 교차 분석)

프로젝트 폴더·첨부 파일을 먼저 읽는다. **내부 자료에서 확인되는 사실과 추정을 구분**하고([추정] 태그), 표의 각 행에 근거 파일명을 표기한다. 관련 파일이 없으면 사용자에게 확인 후 외부 리서치로 진행한다.

### 2단계. 외부 리서치 결합

- 웹 리서치로 보완하되 출처 규율(출력 규칙 1·2) 적용
- **내부 자료와 외부 정보가 다르면 차이를 명시** (숨기지 않는다)
- 출처 등급을 판정해 병기한다 (`references/source-grading.md`): 1차 자료 / 산업보고서 / 언론·2차 인용
- "업계 관계자", "들은 이야기", 자사 발표 수치 단독 인용은 자동으로 [미검증] 또는 교차검증 대상

### 3단계. 3중 검증 (◐작업본)

세 관점을 **각각 따로** 수행한다:

1. **팩트**: 모든 수치·고유명사·인용이 출처와 일치하는가
2. **출처**: 각 주장을 받치는 출처의 등급과 최신성이 충분한가
3. **논리**: MECE 위반, 인과 비약, 숨은 전제, 계산 불일치가 있는가

출력: 관점별 문제 항목 표 + 각 항목에 조치 방안(무엇을 확인해야 하는가). 근거 없이 단정된 수치는 반드시 [미검증] 분류. 검증 프롬프트 전문은 `references/verification-loop.md`.

### 4단계. Red 반론 (◆최종본)

관점을 분리해("작성자 AI는 자기 결론에 우호적이다") 반론자 역할로 전환한다:

- 결론을 무너뜨릴 **반론 3개**, 각각 요지 1문장 + 근거(내부 논리 허점 또는 외부 사실) + 이 반론이 맞다면 결론이 어떻게 달라지는가
- **"더 조사가 필요하다" 같은 일반론은 반론으로 인정하지 않는다**
- 더 깊은 반론이 필요하면 `sz:devil-review` 체이닝

### 5단계. 사람 승인 게이트 → 조건부 결론

- 반론별 수용/기각을 **사용자에게 선택받는다** (스킬이 임의 판정하지 않음)
- 수용된 반론을 반영해 단정형 결론을 **조건부 결론**으로 재작성 (예: "파트너십 우선, 단 ○○ 조건 충족 시 직접 진출 재검토")
- 수정 전/후 결론을 나란히 제시하고 무엇이 달라졌는지 1줄 설명
- 미검증 항목은 1차 리서치(추가 확인) 항목으로 이관 목록화

## 검증 3원칙 (산출물 말미에 명시)

1. AI 초안은 '검증 전 문서'다 — 사람 주니어의 초안과 동일하게 취급하라
2. 검증은 루틴이다 — 이 스킬 호출만으로 동일 품질의 QC가 재현된다
3. 최종 승인은 언제나 사람이다 — 반론 수용 여부와 결론 확정은 사용자의 판단이다

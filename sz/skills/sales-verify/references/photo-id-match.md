# 사진 식별번호 판독·매칭 엔진 (사본 — 정본: sz:sample-log/references/photo-id-match.md)
# 사용 스킬: sz:sample-log(재고실사) · sz:sales-verify(판매 검증) — 수정 시 양쪽 references 동기화

## 1. 판독 (사진 → 식별번호)
- 사진마다 시리얼넘버·IMEI 등 식별번호를 비전으로 추출한다.
- **추측 금지 (HARD)**: 문자 일부가 불명확하면 임의 보정하지 않고 `판독불가`로 분류한다. 오추출 1건은 매칭 오류 2건(허위 매칭 + 실제 항목 누락)으로 번진다.
- IMEI는 **15자리 + Luhn 체크섬 검증** — 검증 실패 = 오판독으로 간주해 판독불가 처리. 듀얼 IMEI는 IMEI1 기준(둘 다 기록).
- 시리얼은 대장/시스템의 형식 패턴(자릿수·접두어)과 대조해 형식 불일치 시 재판독 1회 → 실패 시 판독불가.

## 2. 재촬영(스크린 촬영) 감지 — 진위 단서 동시 점검
| 단서 | 내용 |
|---|---|
| 모아레·픽셀 격자 | 화면 재촬영 시 물결무늬·서브픽셀 패턴 |
| 기기 흔적 | 촬영된 화면의 베젤·모서리, 상태바·앱 UI·갤러리 화면 |
| 광학 특성 | 화면 반사광·백라이트 균일광, 실물 금속/라벨 질감 부재 |
| 맥락 | 실물 맥락 없이 이미지만 꽉 찬 구도, 타임스탬프·워터마크 재촬영 흔적 |
- 단서 발견 시 `재촬영 의심`으로 분류하고 **사유를 명기**한다.
- **자동 리젝 금지 (HARD)**: 재촬영 의심은 사용자 육안 확인 대상으로만 보고한다(오탐으로 인한 불이익 방지).

## 3. 파일명 변경
- 정상 판독 사진: 파일명을 식별번호로 변경(사용자 지정 형식이 있으면 그 형식).
- 동일 번호 중복: `_2, _3` 부여 + 보고서에 중복 표기.
- 판독불가·재촬영 의심: **원본 파일명 유지**(추적성 보존).

## 4. 분류 폴더 표준
| 폴더 | 내용 |
|---|---|
| `01_매칭/` | 사진 번호가 대장/이력에 존재 |
| `02_불일치_사진만/` | 사진에만 있는 번호 |
| `03_판독불가/` | 추출 실패·체크섬 실패 |
| `04_재촬영의심/` | 진위 단서 발견(사유 기록) |
- 대장/이력에만 있고 사진이 없는 항목은 폴더가 아닌 **누락 리스트**로 보고서에 정리.

## 5. 결과보고 표준
요약(총 사진·매칭·사진만·판독불가·재촬영 의심(사유별)·누락) → 상세 표 → 육안 확인 대상 목록(02·03·04 + 누락) → 후속 조치 안내. 최종 판정은 항상 사용자.
